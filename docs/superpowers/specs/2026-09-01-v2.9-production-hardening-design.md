# Segeran Jiwa POS v2.9 Production Hardening Design

## Status
Approved and locked by Owner on 2026-09-01. v2.8 remains the rollback-safe production baseline.

## Goal
Deliver one integrated v2.9 candidate that fixes browser-runtime defects first, then upgrades reporting and finished-goods operations without weakening the frozen transaction/QRIS/inventory/shift/session safety boundaries.

## Global Safety Locks
- Keep Firebase POS root and QRIS root unchanged.
- Keep `baseline/legacy-v1.0.40.html` byte-identical unless a proven blocker forces a separate approval.
- Do not add direct RTDB `.set/.update/.transaction/.remove` calls in modular source.
- Do not duplicate transaction, QRIS, inventory, shift, refund, debt, or session writers.
- Preserve barcode camera, historical date/shift selector, stale-shift recovery, Mini Cart, persistent session, role guards, and displayOrder intent.
- GitHub/Codespaces/Cloudflare remain untouched until the integrated candidate passes fresh-package verification.

## v2.9 Workstreams

### P0 Browser Runtime Fixes
1. **Single receipt surface** — the success receipt is the sole active receipt action surface. Legacy receipt footer must remain hidden even against legacy `!important` CSS.
2. **Cart deletion stability** — remove per-line trash/delete action from the active mobile cart. Quantity decreases use `-`; global `Kosongkan` remains the only bulk-clear action.
3. **Sales-history search focus** — typing transaction/product search must update results without rebuilding the search input, preserving Android keyboard focus.
4. **Profile photo safe persistence** — upload/change/remove must work without Firebase Storage. P0 uses compressed device-persistent avatar storage through the existing browser-storage boundary. Cross-device RTDB avatar persistence is deferred unless a separate writer architecture is approved.
5. **Sales-card copy cleanup** — remove `Siap dijual` from untracked product cards while preserving real stock warnings/quantities.
6. **Header refresh placement** — manual refresh must live inside the header action group instead of being appended as an orphan row.
7. **Operational semantic correction** — current-shift data must not be labelled `Hari Ini`; labels must match the actual data scope until canonical reporting replaces the summary.

### Canonical Reporting v2
One read-only reporting controller with scope hierarchy: Shift / Hari / Minggu / Bulan / Custom. All KPI, payment mix, chart, top products, sales history, and transaction drilldown inherit the active scope. VOID excluded, refund deducted, unknown HPP shown as `Belum tersedia`. Search inputs update result regions in place.

### Finished Goods v2
Owner-first presentation split into Gudang / Gerai / Pergerakan with searchable product picker. Manual warehouse physical stock uses existing Stock Opname authority; warehouse-to-outlet transfer uses existing Inventory V2 transfer authority. Sales consume outlet stock only. Damage/loss/expiry remains draft/reconciliation and never mutates stock directly from Cashier UI.

### Historical Stock Architecture
Historical `stok akhir` must never be fabricated from current balances. If immutable stock snapshots at shift close are later approved, design an additive idempotent snapshot authority separately. Until then historical reports use explicit labels such as `Stok Gerai Saat Ini`.

### Final Audit and Release
Full writer/database audit, flow audit, browser regression coverage, full verifier, frozen-hash check, source manifest, final ZIP, fresh extraction verification, QA handoff, then exactly one GitHub/Codespaces/Cloudflare deployment.

## P0 Data/Writer Decisions
- Receipt, cart, history search, copy cleanup, header layout, and operational labels are presentation/read-model fixes only.
- Profile photo P0 must not create a new RTDB writer. It is stored as a compressed data URL in a user-scoped browser JSON store. This makes upload/remove persistent on the current device and origin while preserving zero-cost/no-schema safety.
- No P0 task may mutate business data or alter frozen legacy transaction semantics.

## P0 Acceptance
- One visible receipt action set after successful payment.
- No per-item trash/delete button in active mobile cart; `-`, `+`, Discount, and top-right `Kosongkan` remain.
- Transaction search can accept continuous typing without focus loss caused by full page rerender.
- Selecting a valid profile image updates avatar immediately and survives page/browser reopen on the same domain/device; using initials clears it.
- Product cards do not show `Siap dijual` for untracked products.
- Refresh is placed in existing header controls, remains deterministic, and does not alter cart/date/shift.
- Operational summary labels never claim `Hari Ini` when their source is only the active shift.
- Full `npm run verify:ref01` remains green; SC-04 stays at zero modular RTDB mutations; frozen baseline SHA256 remains `877dd5d80ad3cfbae9c8ded35ea37c426bf795392240adb96c38e62fc556154f`.
