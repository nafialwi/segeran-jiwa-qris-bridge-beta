# Segeran Jiwa POS v2.9 P0 Browser Runtime Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Fix the seven post-deployment P0 browser-runtime defects without changing frozen business writers or Firebase schema.

**Architecture:** Keep the v2.8 frozen monolith as behavior authority and correct browser presentation through modular refinement layers. Each defect gets a failing regression test, the smallest compatible patch, then full safety verification.

**Tech Stack:** JavaScript ES modules, Node.js built-in test runner, static HTML/CSS compatibility build, Firebase legacy runtime behind frozen compatibility boundaries.

**Spec:** `docs/superpowers/specs/2026-09-01-v2.9-production-hardening-design.md`

## Global Constraints
- Firebase POS/QRIS roots unchanged.
- `baseline/legacy-v1.0.40.html` remains byte-identical.
- Zero direct modular RTDB mutations.
- No duplicate transaction/QRIS/inventory/shift/refund/debt/session writer.
- TDD: RED → minimal GREEN → regression.
- No GitHub/Codespaces/Cloudflare until integrated candidate final.
