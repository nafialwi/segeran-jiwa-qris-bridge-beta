# Segeran Jiwa POS v2.9 Canonical Reporting v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build one read-only sales-report controller for Shift / Hari / Minggu / Bulan / Custom where every KPI, chart, Top Produk, sold-product row, current outlet-stock value, and transaction history inherits the same active scope.

**Architecture:** Keep `SJReportFoundationV010` as the read/cache authority and preserve all legacy writers. Add a pure v2.9 scope/filter domain module and make `report-refinement.js` the canonical presentation/controller. The existing history module consumes the canonical filtered model rather than maintaining a second period/filter truth.

**Tech Stack:** JavaScript ES modules, Node test runner, existing `SJReportFoundationV010`, existing read-only compatibility bridge, existing locked icon/CSS refinement system.

**Spec:** `docs/superpowers/specs/2026-09-01-v2.9-production-hardening-design.md`

## Global Constraints

- Frozen baseline SHA256 must remain `877dd5d80ad3cfbae9c8ded35ea37c426bf795392240adb96c38e62fc556154f`.
- No new direct RTDB `.set/.update/.transaction/.remove` in modular source.
- VOID/CANCELLED excluded; refund deducted.
- Unknown HPP is `Belum tersedia`, never `Rp0`.
- Historical stock must not be fabricated; report labels current balance as `Stok Gerai Saat Ini` until a separately approved stock-snapshot authority exists.
- Cashier remains read-only and keeps Laporan Shift semantics.
- Search query must preserve keyboard focus by partial result updates.
