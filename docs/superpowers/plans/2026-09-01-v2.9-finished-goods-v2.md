# Segeran Jiwa POS v2.9 Finished Goods v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the mixed Gudang/Gerai inventory presentation with one simple finished-goods workflow while preserving the existing Inventory V2 write authorities.

**Architecture:** Keep `SJInventoryV2` as the only mutation authority. Build a read-only finished-goods hub with explicit Gudang / Gerai / Pergerakan tabs and a searchable product picker; actions preselect the chosen finished product in existing Transfer/Opname/Purchase surfaces instead of creating new writers. Cashier exception reporting remains draft + WhatsApp and never mutates stock directly.

**Tech Stack:** JavaScript ES modules, existing Firebase read bridge, existing `SJInventoryV2.open`, Node test runner, locked icon/CSS refinement system.

**Spec:** `docs/superpowers/specs/2026-09-01-v2.9-production-hardening-design.md`

## Global Constraints
- Firebase roots/schema unchanged.
- Frozen baseline SHA256 remains `877dd5d80ad3cfbae9c8ded35ea37c426bf795392240adb96c38e62fc556154f`.
- No new modular `.set/.update/.transaction/.remove`.
- Finished goods only in the primary workflow; recipe/ingredients remain Advanced.
- Set Stok Gudang delegates to existing `SJInventoryV2.open('opname')` with location `warehouse`.
- Gudang → Gerai delegates to existing `SJInventoryV2.open('transfer')`.
- Purchase remains optional Advanced flow; it is not required for manually establishing physical Gudang stock.
- Cashier damage/loss/expiry draft never mutates stock.
- No large product `<select>` in the v2.9 primary finished-goods UI.
